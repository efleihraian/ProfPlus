# P-078 — Aplicație unificată et administrare (2026-10-14)

## Cererea și baza funcțională

Titularul cere combinarea funcțiilor variantei albastre de la localhost:3000 cu designul/paginile verzi, o singură versiune local/main/Site, corectarea antetului mobil și administrare pentru contul indicat, fără pierderea versiunii locale.

Main conține deja codul funcțional P-072/P-073 și shell-ul P-074; previzualizarea P-077 de la 3087 avea numai API proxy sintetic pentru QA, cu cont neconectat și răspuns de test. Nu era altă aplicație de producție. Integrarea păstrează codul contului Supabase, istoric/proiecte, documente, biblioteca/RAG și editorul/exportul; adaugă P-077 și noua administrare. Site primește aceeași implementare `app/lib/public/db/drizzle`, păstrând configurația hosting/build existentă. Nu înlocuiește baza de date cu fixture-uri.

Copia operațională veche rămâne intactă. Backup local comprimat (62 MB, mod 0600), în directorul privat `~/dev/profplus-backups/`, exclude dependențele/buildul/Git și păstrează fișierele de lucru/configurația privată. Nu intră în Git sau Site. Checkout-ul unificat este `~/dev/profplus-P-077-exercise-mix`; localhost:3000 pornește din `web` în acest checkout, cu configurația locală existentă și o copie a stării locale. Conturile/conversațiile/documentele cloud nu sunt migrate ori șterse. Preview-ul 3087 se închide după verificare.

## Navigare și funcții

Antet desktop: siglă, navigare, temă și cont aliniate. La lățimi intermediare contul rămâne lângă siglă și navigarea pe al doilea rând. Sub 480 px, toate cele patru secțiuni sunt vizibile în două coloane; contul nu cade singur pe un rând. Toolbarul mobil al asistentului are meniu și temă, fără brand duplicat. Preferința de temă a asistentului este păstrată; portofoliul și clasele păstrează stocarea locală și limitele P-074 (nu se declară sincronizare cloud ori exportul opisului implementate).

Biblioteca reală observată prin API: 9.538 materiale comune, 9.525 selectate automat, zero documente private pentru guest. Selecțiile automate se trimit compact și se recalculează pe server. Plafonul manual este 10.000 materiale comune/50 documente, ca trecerea din automatic la manual după deselectare să poată păstra biblioteca actuală; limitele corpului cererii nu cresc. Cazul de 9.600 materiale și refuzul peste 10.000 sunt testate.

## Admin și știri

Apartenența este într-o tabelă server-only `profplus_admins`, legată de `auth.users.id` cu cascade la ștergerea contului. Contul solicitat a fost identificat prin e-mailul confirmat și înscris prin operație SQL controlată; e-mailul și ID-ul nu sunt hardcodate în frontend ori migration. Nu schimbă profilul didactic și nu acordă acces la conversațiile/documentele altora. `GET /api/account` întoarce un boolean pentru afișarea legăturii Admin; fiecare endpoint admin verifică din nou identitatea și tabela, refuzând conturi în curs de ștergere, Sites sau neconfirmate. `user_metadata`, câmpurile client și e-mailul trimis de client nu conferă rol.

Dashboard `/admin`: numărări agregate (conturi cu date în aplicație, conversații, proiecte, documente/stare, biblioteca comună/indexare și știri), jurnal minim și editor. Nu este numărătoare a tuturor înscrierilor și nu expune mesajele ori originalele private. Configurarea secțiunii permite titlu și introducere. Articolele au titlu, rezumat, text simplu, categorie, imagine HTTPS opțională, sursă HTTPS opțională, poziție 0–3 și stare draft/published/archived. Pagina Acasă păstrează articol principal + trei secundare și legătura la toate știrile; fără articole publicate arată starea goală, fără titluri inventate. `/news` afișează text inert, fără HTML executabil.

Publicarea ocupă o poziție unică; pentru înlocuire se arhivează articolul anterior, apoi se publică noul articol. API nu șterge definitiv articole. Revizia numerică previne suprascrierea unei versiuni editate concomitent; conflictul întoarce 409. Scrierea și auditul sunt în aceeași tranzacție RPC, cu membership verificat încă o dată. Operațiile jurnalului se elimină la următoarea modificare dacă au peste 90 zile; actorul devine null la ștergerea contului. Nu există job zilnic de retenție; limita reală este documentată. Știrile editoriale și setările rămân după ștergerea unui admin.

Toate cele patru tabele au RLS și granturi revoke pentru PUBLIC/anon/authenticated; numai backendul service_role le citește/modifică. Funcțiile SQL sunt SECURITY INVOKER, execute revocat pentru PUBLIC/anon/authenticated. Endpointul public livrează numai published cu data trecută/prezentă și DTO explicit. Admin nu primește chei/SQL arbitrar. Corp și câmpuri limitate, same-origin și JSON obligatoriu, URL-uri HTTPS fără credențiale; imaginile externe nu primesc referer, pot implica acces la gazda aleasă de editor. CSP permite HTTPS numai pentru imagini, ca știrile cu imagine să se afișeze; script/connect/object păstrează restricțiile existente.

## Configurație, verificare și limite

Site păstrează accesul owner-private și se configurează cu același Supabase ca local: AUTH_PROVIDER=supabase, APP_ORIGIN=URL-ul Site, Google/Apple active, Email/registration dezactivate. Publishable key existentă păstrată exclusiv server; secretele OpenAI/Supabase existente nu se schimbă. Sites continuă să protejeze accesul exterior la pilot. Autentificarea OAuth reală în browser nu a fost executată ca titular; nu se pretinde test Google/Apple sau că setările redirect ale providerului au fost auditate în această livrare.

Teste Node: membership persistentă, refuz metadata/admin din client, CSRF, tip/limite, actor stabilit pe server, filtre publicare și text inert. Suite normale cont/ownership/deletion/profile/source și P-077 trecute, cu Auth/AI simulate. În baza reală, `tests/admin_news.sql` verifică scrieri/revizii/sloturi, refuz actor absent, anon și authenticated, apoi ROLLBACK pentru toate fixture-urile și auditul lor. Verificare granturi/RLS și cont admin confirmată. Advisor: zero avertismente/erori, numai 8 INFO RLS-no-policy pentru tabele server-only intenționat inaccesibile rolurilor publice, patru preexistente și patru noi.
